## Этап 1: внешний сервис публикации

- Первый кандидат — `https://t.me/posted`; можно выбрать другой сервис, сохраняющий премиум-эмодзи.
- Наш бот остаётся редактором и контент-планом. Внешнему сервису передаются основной пост, напоминания, серии без поста, расписание и таймеры удаления.
- Для взаимодействия допустим отдельный Premium-аккаунт; аккаунт уже есть, тестовый канал нужно подключить.
- Коллекционное имя для нашего бота не требуется в целевой схеме; у владельца есть Premium, купленное имя к боту не привязано.
- Фото в цитате после текста обязательно с первого теста. Сохранение custom emoji и форматирования обязательно. Остальной начальный набор функций уточняется по результату проверки возможностей сервиса.
- Внесённые вручную в сервисе правки желательно синхронизировать обратно, но это не первая задача.
- При ошибке внешнего сервиса — повторная попытка и уведомление. Автоматического перехода на прямую публикацию нет.
- Существующие серии завершаются прежним способом; новая схема применяется к новым сериям после успешного теста. Для задания фиксируется выбранный механизм публикации, чтобы не возникало двойных отправок.
- Расходы оцениваются по мере реализации, отдельный бюджет заранее не установлен.
- Каждый будущий пользователь подключает собственный аккаунт сервиса/Telegram. Чужие сессии и токены не разделяются между пользователями.

Текущий подэтап: изолированный инструмент входа и чтения меню Posted. Он не публикует сообщения. Следующий шаг — изучить реальное меню подключённого аккаунта и проверить фото-цитату, эмодзи, URL-кнопку, расписание и удаление в тестовом канале. Пока не подтверждено, что все эти операции доступны для автоматизации через Posted.

## Этап 2: многопользовательский сервис

- Вход через `/start` открыт всем. Начальная оценка — до 100 пользователей, с возможностью расширения.
- Канал подключается пользователем через выбор канала или пересылку его поста после выдачи боту админских прав.
- Пользователь видит только лично подключённые каналы и может создавать публикации только в них.
- Один канал могут подключить несколько его администраторов. Они видят и редактируют общую очередь постов нашего бота в этом канале. Черновики остаются личными.
- На первом этапе прав доступа достаточно статуса администратора. Проверка выполняется при взаимодействии с ботом, а не постоянным опросом всех пользователей.
- При потере админки доступ закрывается, очередь канала сохраняется. Нужно отдельно проверить, как внешний сервис ведёт себя при потере прав у владельца его подключения.
- Удаление канала пользователем убирает его только из личного списка. Оно не отключает канал у других пользователей и не отменяет общую очередь.
- Список каналов и объединение их в сетки личные у каждого пользователя; публикация в отдельный канал также поддерживается.
- Текстовые шаблоны личные и используются во всех подключённых пользователем каналах.
- Уведомления о публикациях и ошибках получают все подключившие канал администраторы с актуальным доступом.
- Канал хранится как одна общая сущность; подключения пользователей и их сетки — отдельные связи. Повторное добавление канала другим пользователем не дублирует посты.

Перед реализацией связанных копий нужно явно определить действие общей правки серии на копии в каналах, которые пользователь лично не подключил. Новое правило запрещает показывать такие каналы и создавать в них посты; старое поведение обновляло связанные копии целиком. Это пересечение не должно разрешаться молча.
