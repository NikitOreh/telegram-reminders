# Развёртывание в Yandex Cloud (Россия)

Бот работает через Telegram long polling. Ему нужна одна постоянная ВМ Linux с доступом в интернет; домен, открытый HTTP-порт, балансировщик и управляемая база данных не нужны. Новый сервер устанавливается без запуска бота: одновременный запуск локального и облачного экземпляров с одним токеном приведёт к конфликту polling и может нарушить публикации.

## Виртуальная машина

1. В [Yandex Cloud Console](https://console.yandex.cloud/) подключите платёжный аккаунт и откройте Compute Cloud → Виртуальные машины → Создать. Выберите **регион Россия**, Ubuntu 24.04 LTS, обычную (не прерываемую) ВМ. Для текущей нагрузки подходит 2 vCPU с долей 50%, 2 ГБ RAM и 20 ГБ SSD. Если важна минимальная цена, можно начать с [готовой минимальной конфигурации](https://yandex.cloud/ru/services/compute) на 2 ГБ RAM и 13 ГБ HDD и следить за свободным местом. Сумму перед созданием проверьте в калькуляторе консоли.
2. Выберите доступ по SSH-ключу, логин `yc-user` и загрузите **открытый** ключ `~/.ssh/telegram-reminders-yc.pub`. Закрытый ключ без расширения остаётся только на вашем компьютере; в консоль его не загружайте. Назначьте публичный IPv4. В группе безопасности откройте входящий TCP 22 **только с вашего IP**, исходящий HTTPS (TCP 443) оставьте разрешённым. Другие входящие порты боту не нужны. Официальная [инструкция по созданию ВМ](https://yandex.cloud/ru/docs/compute/quickstart/quick-create-linux) и [подключению по SSH](https://yandex.cloud/ru/docs/compute/operations/vm-connect/ssh).
3. Подключитесь с Windows: `ssh -i "$env:USERPROFILE\.ssh\telegram-reminders-yc" yc-user@ПУБЛИЧНЫЙ_IP`.

## Подготовка без остановки локального бота

На Windows из папки проекта выполните `powershell -File .\deploy\yandex\package.ps1`. Скрипт создаст архив в `%TEMP%`, включая текущий `data.json` и `.env` без неиспользуемого ключа OpenAI, но без Windows `node_modules` и кэша. Архив содержит токен Telegram: не публикуйте его. Скопируйте архив на ВМ:

```powershell
scp -i "$env:USERPROFILE\.ssh\telegram-reminders-yc" ПУТЬ_К_АРХИВУ yc-user@ПУБЛИЧНЫЙ_IP:~/telegram-reminders.tar.gz
```

На ВМ распакуйте во временную папку и установите приложение:

```bash
mkdir -p ~/telegram-reminders-stage
tar -xzf ~/telegram-reminders.tar.gz -C ~/telegram-reminders-stage
sudo bash ~/telegram-reminders-stage/deploy/yandex/install.sh ~/telegram-reminders-stage
```

Установщик скачивает Node.js 22 с официального сайта, сверяет SHA-256, устанавливает зависимости для Linux, проверяет доступ бота к Telegram и каналам и регистрирует `systemd`-службу. **Он не запускает и не включает бота.** На этом этапе локальный экземпляр продолжает публиковать сообщения.

## Переключение

Выберите несколько минут без запланированных публикаций. Остановите локальный процесс бота. **После остановки** сделайте новый архив, передайте его на ВМ и повторите три команды установки выше: это перенесёт последнюю версию `data.json` с очередью и `offset`. Затем на ВМ:

```bash
sudo systemctl enable --now telegram-reminders
sudo systemctl status telegram-reminders --no-pager
sudo journalctl -u telegram-reminders -n 30 --no-pager
```

Проверьте `/start` в личном чате, контент-план и одну тестовую публикацию. После успешного переноса удалите оба архива с `.env` и временную папку на ВМ. Локальный бот не запускайте одновременно с облачным.

Служба автоматически запускается после перезагрузки ВМ. Таймер каждые шесть часов копирует и проверяет `data.json`, хранит локальные копии 14 дней в `/var/backups/telegram-reminders`. Эти копии находятся на том же диске; для защиты от потери ВМ дополнительно настройте снимки диска или внешнюю копию файла. Проверить таймер: `systemctl list-timers telegram-reminders-backup.timer`.

На сервере доступ к `.env` и `data.json` ограничен пользователем `reminderbot`. Бот не использует OpenAI API и не нуждается в ключе OpenAI.
